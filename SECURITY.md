# Security Policy

## Supported Versions

Security fixes are generally applied to the latest published release. Older releases may
not receive fixes; please update to the latest available version before reporting an issue.

| Version | Supported |
| ------- | --------- |
| Latest release | :white_check_mark: |
| Older releases | :x: |

## Reporting a Vulnerability

Please do **not** report security vulnerabilities in public GitHub issues, pull requests,
or discussions.

Use GitHub's **Report a vulnerability** option on this repository's **Security** tab to
submit a private vulnerability report, if private vulnerability reporting is enabled.
If that option is unavailable, contact the repository owner through the GitHub profile:

https://github.com/marufallammahim

When reporting, include as much of the following information as possible:

- A clear description of the vulnerability and its potential impact.
- The affected app version, Android version, and device model (if relevant).
- Reproduction steps or a minimal proof of concept.
- Any relevant logs or screenshots, after removing passwords, tokens, personal data,
  and other secrets.

Please allow up to **7 days** for an initial response. We will investigate the report,
may ask for additional details, and will communicate whether the issue is accepted,
being investigated, or not considered a security vulnerability. Please allow reasonable
time for a fix before publicly disclosing a confirmed issue.

## Scope

Reports may cover the Android application, its release artifacts, dependencies, and
project infrastructure where they create a security risk. Do not attempt to access,
modify, or disrupt another person's device, account, or data while testing.
